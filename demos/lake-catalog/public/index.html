Lake Catalog

Quack, policies, and one object per catalog

What this proves A DuckLake-style catalog can live on Workers. DuckDB’s Quack HTTP protocol hits POST /quack. A registry Durable Object routes each catalog to its own SQLite object. JWT roles are checked against row and column rules before SQL runs. The sample table is also Parquet in R2.

What to try

  • Pick analyst, viewer, or guest and run a sample statement.
  • Read whether the policy allows the SQL, denies it, or rewrites it.
  • Open the side panel to see each catalog’s Durable Object and R2 path.
  • Copy the DuckDB CLI snippet. The token is read-only and lasts ten minutes.

What you could build

  • A shared catalog in front of Parquet you already keep in R2.
  • One catalog per team, each with its own Durable Object and policy.
  • Short-lived tokens so analysts query from DuckDB without a warehouse login.
